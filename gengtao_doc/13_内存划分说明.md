# 13 内存划分说明

本文讲 **RAM**（PSRAM + 片内 SRAM），不是 Flash 分区。Flash 见 [11_分区说明.md](11_分区说明.md)。

本项目芯片配置：`CONFIG_CHIP_8910_NOR8M_PSRAM16M`  
**8MB NOR + 16MB PSRAM**。VoLTE 打开时 AP 只拿到其中 **4MB**，其余给 CP/modem。

> 数值来自本次 release：`target/C51/prepack/target.cmake`、`chip_8910.cmake`、`8915DM_cat1_open.map`、`C51_APP.map`。  
> `build_all.sh` 在 `VOLTE` 时写 `ap_ram_offset=0xC00000`、`ap_ram_size=0x400000`。

---

## 1. 整机两块内存

| 介质 | 物理基址 | 总长 | 宏 |
|------|----------|------|-----|
| 片内 SRAM | `0x00800000` | 256KB (`0x40000`) | `CONFIG_SRAM_PHY_ADDRESS` / `CONFIG_SRAM_SIZE` |
| PSRAM | `0x80000000` | 16MB (`0x1000000`) | `CONFIG_RAM_PHY_ADDRESS` / `CONFIG_RAM_SIZE` |

NOR XIP 在 `0x60000000`，那是代码只读映射，不算这份 RAM。

```
SRAM  0x00800000 ──────── 256KB ──────── 0x00840000
      AP 只用开头约 8KB（含栈/蓝屏），其余启动/CP/共享

PSRAM 0x80000000 ──────────── 16MB ──────────── 0x81000000
      |<------ CP / IMS 约 12MB ------>|<-- AP 4MB -->|
      0x80000000                    0x80C00000    0x81000000
```

---

## 2. PSRAM：CP 和 AP 怎么切

`CONFIG_APP_RAM_OFFSET` + `CONFIG_APP_TOTAL_RAM_SIZE` 从 PSRAM **尾部**切给 AP。

| 组合 | AP 偏移 | AP 总长 | AP 窗口 | CP 大约 |
|------|---------|---------|---------|---------|
| **VOLTE（当前）** | `0xC00000` | `0x400000`（4MB） | `0x80C00000`–`0x81000000` | 低 12MB |
| NOVOLTE | `0x980000` | `0x680000`（6.5MB） | `0x80980000`–`0x81000000` | 低 9.5MB |

VoLTE / IMS 要更多 CP 内存，所以 AP 从 6.5MB 收到 4MB。脚本和分区 JSON 必须配套换，不能只改一边。

---

## 3. AP 这 4MB 再切三刀

`chip_8910.cmake` 从 AP 窗口 **高地址往低切**：

```
BTFW      = TOTAL 末尾 256KB
FILEIMG   = 再往下（本项目 0）
FLASHIMG  = 再往下 128KB   ← 客户 APPIMG 的 .data/.bss
剩下      = 内核链接用的 ram（heap 也在这里）
```

本项目算出来：

```
CONFIG_APP_BTFW_RAM_OFFSET     = 0xC00000 + 0x400000 - 0x40000  = 0xFC0000
CONFIG_APP_FLASHIMG_RAM_OFFSET = 0xFC0000 - 0x20000             = 0xFA0000
CONFIG_APP_RAM_SIZE            = 0xFA0000 - 0xC00000            = 0x3A0000   (3.625MB)
```

对应物理地址：

```
0x80C00000                        0x80FA0000     0x80FC0000     0x81000000
|<----- 内核 ram 3.625MB -------->|< APP 128KB >|< BT 256KB >|
   ttbl / data / bss / heap          APPIMG RW      蓝牙固件
```

`flashrun.ld` 里内核 `ram` 段就是 `0x80C00000` 长 `0x3A0000`。  
客户应用 `app_flashimg.ld` 的 `ram` 是 `0x80FA0000` 长 `0x20000`。

---

## 4. 内核 RAM 和客户 RAM 怎样隔开

**不是两个进程，也不是给客户单独做了一套 MMU 保护。** 同一套 Cortex-A5、同一份页表、同一特权级。隔开靠三件事叠在一起：编的时候地址对不上、堆到边界停、加载时只允许写那 128KB。

### 4.1 链接时切成两个不重叠的 `MEMORY`

两份 ELF、两份脚本，窗口在 CMake 里算好，首尾相接、互不包含：

| | 脚本 | `ram` ORIGIN | LENGTH |
|--|------|--------------|--------|
| 内核 | `flashrun.ld` | `0x80000000 + APP_RAM_OFFSET` | `APP_RAM_SIZE`（3.625MB） |
| 客户 | `app_flashimg.ld` | `0x80000000 + FLASHIMG_RAM_OFFSET` | `0x20000` |

内核目标文件的 `.data/.bss` 只能进第一段；客户的只能进第二段。链错段会 `RAM overflow`。

内核堆顶故意等于客户窗口起点：

```c
__heap_start = __ram_end;                          // 静态段后面
__heap_end   = ORIGIN(ram) + LENGTH(ram);          // = 0x80FA0000
```

所以内核 `malloc` **按设计不会**分到 `0x80FA0000` 之后（那是客户静态区 / BT）。

### 4.2 加载时只拷规定窗口

`app_loader.c` 从 Flash `0x60250000` 读 APPIMG 头，按段操作：

| 段类型 | 动作 | 目的地必须在 |
|--------|------|----------------|
| XIP | 不拷，就地执行 | Flash APPIMG 2MB |
| COPY | `memcpy` → `.data` / corestub | `0x80FA0000` 起 128KB |
| CLEAR | `memset` → `.bss` | 同上 |
| STUB | 填内核 API 跳板 | 同上 |

目的地若不在 `FLASHIMG_RAM_START ~ +SIZE` 里，加载失败。入口 `appimg_enter` 的地址也必须落在镜像或这 128KB。  
这样客户镜像**写不进**内核 3.625MB，也写不进 BT 256KB（除非镜像头被改坏且检查被绕过）。

### 4.3 MMU 隔的是 AP 和 CP，不是内核和客户

`halShmemUpdateRamAccess()`：

```c
APP_RAM_START = 0x80C00000;
APP_RAM_END   = 0x80C00000 + 0x400000;   // 整个 4MB
// CP 占用的低 12MB：AP 侧标成只读/共享
// AP 这 4MB（内核 + APPIMG + BT）都是 AP 可写
```

客户野指针仍可以打到内核堆、页表。这是 OpenCPU「应用当普通函数跑在内核里」的模型，不是 Linux 用户态。

### 4.4 动态内存反而在内核堆里

`ql_rtos_task_create`、LVGL `malloc` 全屏缓冲，都向**内核堆**要。客户和内核在堆上是共用的，只靠分配器记账，没有物理隔开。

```
隔开的：客户 .data/.bss（128KB）↔ 内核静态+堆（3.625MB）
不隔开的：客户 malloc / 任务栈 ↔ 内核 malloc（同一片堆）
```

## 5. 内核 ram 里实际怎么用（本次 C51）

map：

| 符号 | 地址 | 说明 |
|------|------|------|
| `__ram_start` | `0x80C00000` | 页表、bscore、data、bss |
| `__ram_end` / `__heap_start` | `0x80C61320` | 静态用掉约 **397KB** |
| `__heap_end` | `0x80FA0000` | 堆顶 = FLASHIMG 起点 |
| 堆大小 | ≈ **3.24MB** | `0x80FA0000 - 0x80C61320` |

堆给 `malloc` / `ql_rtos` 任务栈 / LVGL 全屏缓冲（128×128×2 ≈ **32KB**，在 `lvgl_demo.c` 里 `malloc`）。客户 `ql_rtos_task_create` 的栈也从这里出，不占 APPIMG 那 128KB。

页表 `ttbl` 16KB 对齐；蓝屏记录 `CONFIG_BSCORE_SIZE=0x2000`。

编完日志里的 `bss, ram` 是 **内核静态段**，不是整份 16MB，也不是客户 128KB。

## 6. 客户 APPIMG 的 128KB

| | 值 |
|--|----|
| 起点 | `0x80FA0000` |
| 长度 | `CONFIG_APP_FLASHIMG_RAM_SIZE` = `0x20000` |
| 本次 `C51_APP` 用到 | `__ram_end = 0x80FAA8E0` ≈ **43KB**（core_stub + data + bss） |
| 剩余 | ≈ 85KB，链接脚本 **没有**再划应用堆；多出来的不能当第二套 heap 用 |

代码（text/rodata）在 Flash `0x60250000`（2MB APPIMG 区）XIP，不占这 128KB。

`.data` / `.bss` 涨过 128KB 会 `RAM overflow`，应用链不过。大块运行时内存请 `malloc`（走内核堆）。

---

## 7. 片内 SRAM（256KB）

AP 运行时只用窗口：

| 项 | 地址 | 大小 |
|----|------|------|
| APP SRAM | `0x800100` | `0x1F00`（7.75KB） |
| 共享 SHMEM | `0x802000` | `0x1000`（4KB） |

`flashrun.ld` 把中断/SVC/蓝屏栈放在这 7.75KB **尾部**：

| 栈 | 大小 |
|----|------|
| IRQ | `0x200`（512B） |
| SVC | `0x600`（1.5KB） |
| 蓝屏 | `0x400`（1KB） |

本次 map：SRAM 堆 `0x800E60`–`0x801400`（约 1.4KB），给必须放 SRAM 的热路径。`.sramtext` 有 irq / blue_screen / 延时等。

下载阶段 FDL 会占用更多 SRAM（`FDL1` 在 `0x8000C0`，`FDL2`/`BOOT2` 在 `0x810000` 起 192KB），和运行时 AP 窗口不是同一套布局。

## 8. 和客户开发的关系

| 客户会碰到的 | 在哪 | 紧不紧 |
|--------------|------|--------|
| UI 代码、图、字库 | Flash APPIMG 2MB | 本次 img ≈ 1.6MB，先看这个 |
| 全局变量、bss | PSRAM `0x80FA0000` 共 128KB | 本次 ≈ 43KB |
| `malloc`、LVGL buf、任务栈 | 内核堆 ≈ 3.24MB | 一般够 128 屏；升 240 屏全缓冲约 112KB，要重估 |
| 开 VoLTE | AP 总 ram 从 6.5MB 变 4MB | 堆跟着缩 |

不要把「16MB PSRAM」理解成客户有 16MB。VoLTE 下客户能间接用的主要是 **内核堆约 3MB + 应用静态 128KB**。

---

## 9. 改内存要动哪里

| 目的 | 改什么 |
|------|--------|
| 开关 VoLTE | `build_all.sh` 的 `ap_ram_offset` / `ap_ram_size`（已按 VOLTE/NOVOLTE 自动切） |
| 给 APPIMG 更大运行时 ram | `CONFIG_APP_FLASHIMG_RAM_SIZE`（会吃掉内核堆） |
| 关蓝牙省 256KB 给 AP | `CONFIG_APP_BTFW_RAM_SIZE`（要确认 BT 不用） |
| 换 32MB 内存模组 | 不是当前 `NOR8M_PSRAM16M`，整套 Kconfig / 芯片配置都要换 |

改完必须重链内核和应用，整包重下。

---

## 10. 一句话

当前是 **16MB PSRAM 尾部 4MB 给 AP**（VoLTE）：其中 **3.625MB 内核（堆约 3.24MB）+ 128KB 客户静态 + 256KB 蓝牙**。片内 SRAM 256KB 里 AP 只用约 8KB 放中断栈和热代码。客户改 UI 先看 Flash 2MB；全局变量看 128KB；`malloc` 看内核堆。
