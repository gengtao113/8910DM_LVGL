# 08 W25Q128JVSIQ 适配说明

对照规格书 `C97521_NOR+FLASH_W25Q128JVSIQ_规格书_WJ1858289.PDF`（Winbond W25Q128JV Rev.M）和现有 `drv` / `HAL` / `prop.csv`，说明这块 16MB NOR 要怎么接到当前框架上。

结论先说：**不需要新写一套驱动。** 擦写、XIP、suspend、命令集都已按 Winbond/GD 兼容实现。要做的是在型号表里点名这颗片，并确认它是主片还是外挂、分区容量是否按 16MB 配。

---

## 1. 规格书里这颗片是什么

料号 **W25Q128JVSIQ**：

| 段 | 含义 |
|----|------|
| W25Q128JV | 128Mbit / **16MB**，3.0V（2.7–3.6V），Standard/Dual/Quad SPI |
| S | SOIC 208-mil |
| IQ | 工业温，**出厂 QE=1**（Quad 默认开，可直接 XIP） |

阵列：65536 × 256B 页；擦除 4KB / 32KB / 64KB / 全片；4096 个 4K 扇区，256 个 64K 块。支持 XIP、Erase/Program Suspend、volatile SR、SFDP、64-bit UID、3×256B Security Register。

JEDEC `9Fh`（IQ/IN/JQ，**不是** DTR 的 IM/JM）：

```
Manufacturer  EFh
Memory Type   40h
Capacity      18h     → 2^24 = 16MB
```

软件 mid（与现有 `W25Q64JV = 0x1740ef` 同一拼法）：

```
mid = (0x18 << 16) | (0x40 << 8) | 0xEF = 0x1840EF
```

IM/JM（DTR，ID=`7018h`）不要用这行，那是另一份手册。

---

## 2. 现有框架已经覆盖的部分

`HAL_SPI_FLASH_TYPE_WINBOND` 在 HAL 里和 GD 走同一套 StatusCheck、Security Register、QE。表里已有：

```
W25Q64JV,0x1740ef,...   // 8MB 亲兄弟
WINBOND,0x0000EF,...    // 厂商兜底
```

`0x1840EF` **没有**精确行。启动时三级匹配会落到 `WINBOND` 兜底：容量仍按 mid 算出 16MB，能力字段抄 8MB 那套。多数能跑，但 WP 按 16MB 要用 `gGD128MWpMap`，精确入表更稳，也避免以后改兜底误伤 128M。

**不需要改的代码：**

- `drv_spi_flash.c`：open/read/write/erase、XIP、suspend 循环
- `hal_spi_flash.c`：opcode、WIP、volatile WP、Security
- 新 type / 新命令函数

**需要补的：** `hal_spi_flash_prop.csv` 增加一行（插在 `WINBOND` 兜底之前）。

## 3. 规格书 ↔ 软件函数对照

### 3.1 识别与初始化

| 规格书 | opcode | 软件 | 说明 |
|--------|--------|------|------|
| Read JEDEC ID | `9Fh` | `prvReadId` → `halSpiFlashInit` | 得到 `EF 40 18` |
| 按 ID 填属性 | — | `prvFlashPropsByMid` | 查 CSV |
| 上电修 SR、置 QE | `01h/31h` 等 | `halSpiFlashStatusCheck` → `prvStatusCheckGD` | WINBOND 走 GD 分支 |
| 软复位 | `66h`+`99h` | 同上，WIP/WEL/SUS 残留时 | |
| Quad Enable QE=S9 | SR2 | `sr \|= GD_SR_QE` | IQ 出厂已是 1 |

驱动入口：`drvSpiFlashOpen(DRV_NAME_SPI_FLASH 或 _EXT)` → `halSpiFlashInit`。

### 3.2 读 / 写 / 擦（阵列）

| 规格书 | opcode | HAL | 驱动 |
|--------|--------|-----|------|
| 阵列读 | AHB/XIP，不用 `03h` | — | `drvSpiFlashRead` / `MapAddress`：映射 memcpy |
| Page Program 1–256B | `02h` | `halSpiFlashPageProgram` | `drvSpiFlashWrite` 按 256B 切 |
| Sector Erase 4KB | `20h` | `halSpiFlashErase(size=4K)` | `drvSpiFlashErase` |
| Block Erase 32KB | `52h` | size=32K | 对齐则优先 |
| Block Erase 64KB | `D8h` | size=64K | 对齐则优先 |
| Chip Erase | `C7h` | `halSpiFlashChipErase` | `drvSpiFlashChipErase` |
| Write Enable | `06h` | `halSpiFlashWriteEnable` | Prepare 里自动发 |
| BUSY / WIP = S0 | `05h` | `halSpiFlashIsWipFinished` | XIP 路径由 drv 轮询 |

规格书要求：PROGRAM/ERASE 前必须 WREN；写不满一页可以；跨页由驱动切。驱动**不会**自动擦，先 `Erase` 再 `Write`。

### 3.3 Suspend（主片 XIP 关键）

| 规格书 | opcode | HAL | 驱动 |
|--------|--------|-----|------|
| Erase/Program Suspend | `75h` | `halSpiFlashEraseSuspend` / `ProgramSuspend` | `prvErase` / `prvPageProgram` 见 IRQ 则调用 |
| Resume | `7Ah` | `...Resume` | 出临界区后再关 AHB 恢复 |
| SUS = S15 只读 | SR2 bit7 | `has_sus1=1` → `GD_SR_SUS1` | 上电若 SUS 置位则复位 |
| 无第二 SUS 位 | — | `has_sus2=0` | 与 W25Q64JV 相同 |

规格书：suspend 后除读 SR、resume 外，阵列可读（XIP 才能继续）。驱动在 suspend 后开 AHB、出临界区，就是为这个。

CSV 必须 **`suspend_en=1`**。写成 0 会在主片擦 64K 时长时间关中断。

### 3.4 状态寄存器与写保护

规格书三组 SR：

| 寄存器 | 读 / 写 | 软件 |
|--------|---------|------|
| SR1（BUSY/WEL/BP0-2/TB/SEC/SRP） | `05h` / `01h` | `prvReadSR1` / `prvWriteSR1` |
| SR2（SRL/QE/LB1-3/CMP/SUS） | `35h` / `31h`，或 `01h` 一次写 SR1+2 | `has_sr2=1`，`write_sr12=1` |
| SR3（WPS/DRV） | `15h` / `11h` | **当前 HAL 不读写 SR3** |

规格书写保护两套（SR3.WPS）：

| WPS | 规格书 | 软件现状 |
|-----|--------|----------|
| 0（出厂默认） | CMP + SEC + TB + BP[2:0] | HAL `wp_type=GD`，16MB 用 `gGD128MWpMap` |
| 1 | Individual Block Lock（`36h/39h/3Dh/7Eh/98h`） | **未实现**。上电若 WPS=1，整片 Individual Lock 默认锁死 |

适配约定：**保持 WPS=0**（出厂默认）。不要发 `11h` 去置 WPS。BP 位与 GD 宏对应：

```
GD_SR_BP0/1/2 = 规格书 BP0/1/2
GD_SR_BP3     = TB
GD_SR_BP4     = SEC
GD_SR_CMP     = CMP (S14)
```

与手册 7.1.8 保护表一致。`halSpiFlashPrepareEraseProgram` 用 `50h` 写 volatile SR，临时降低 BP；`Finish` 再锁全片。

驱动另有 64KB **软件** `block_prohibit`（`drvSpiFlashSetRangeWriteProhibit`），和芯片 BP 不是一回事。Bootloader 建议两套都锁。

### 3.5 UID / SFDP / Security / 低功耗

| 规格书 | opcode | 软件 | CSV |
|--------|--------|------|-----|
| Unique ID 64bit | `4Bh` + 4 dummy | `halSpiFlashReadUniqueId` | `UID_4BH_8` |
| SFDP | `5Ah` | `halSpiFlashReadSFDP` | `sfdp_en=1` |
| Security 擦/写/读 | `44h` / `42h` / `48h` | WINBOND 走 `prvSreg*44/42/48H`，地址 `num<<12` | 块 256B，编号 1–3 |
| 规格书地址 | SR1=`001000h` 段，SR2=`002000h`，SR3=`003000h` | `num=1,2,3` → `0x1000/2000/3000` | 对齐 |
| LB1/LB2/LB3 OTP | SR2 | `prvSregLockGD` | 一次锁定永久只读 |
| Deep Power-down | `B9h` / `ABh` | `DeepPowerDown` / `Release...` | 唤醒后 HAL 再延时 |

Winbond `4Bh` 没有规格书里的独立 CPID。`W25Q64JV` 仍标了 `CPID_4BH`（多读 18 字节取尾）。128M 建议 **`cpid_type=0`**，避免当芯片 ID 用。

## 4. 建议的 CSV 行

插在 `WINBOND` 兜底之前、`W25Q64JV` 附近：

```csv
W25Q128JV,0x1840ef,0x1000000,HAL_SPI_FLASH_TYPE_WINBOND,HAL_SPI_FLASH_WP_GD,0,HAL_SPI_FLASH_UID_4BH_8,256,1,3,1,1,1,1,1,1,0
```

与 `W25Q64JV` 的差异只有：**mid、capacity、cpid_type**。其余列必须一致：

| 列 | 值 | 依据 |
|----|----|------|
| type | WINBOND | 与 64M 相同命令集 |
| wp_type | GD | BP/TB/SEC/CMP 兼容，16MB 走 `gGD128MWpMap` |
| cpid_type | 0 | 手册只有 64-bit UID |
| uid_type | 4BH_8 | `4Bh`，8 字节 |
| sreg_block_size | 256 | 3×256B |
| sreg_min/max | 1 / 3 | LB1–LB3 |
| volatile_sr_en | 1 | `50h` |
| suspend_en | 1 | `75h/7Ah`，SUS=S15 |
| sfdp_en | 1 | `5Ah` |
| write_sr12 | 1 | `01h` 可写 SR1+SR2 |
| has_sr2 | 1 | `35h` |
| has_sus1 | 1 | S15 |
| has_sus2 | 0 | 无 GD 第二 SUS |

改完重编 `components/hal`（`norpropgen.py` 会重新生成 `hal_spi_flash_prop.h`）。

## 5. 驱动层怎么用（不用改实现）

主片（代码也在这颗 NOR 上，XIP 必须开）：

```c
drvSpiFlash_t *f = drvSpiFlashOpen(DRV_NAME_SPI_FLASH);
/* 可选：锁 boot 区，64KB 对齐 */
drvSpiFlashSetRangeWriteProhibit(f, 0, 0x10000);

drvSpiFlashErase(f, offset, size);          /* offset/size 4K 对齐 */
drvSpiFlashWrite(f, offset, data, size);    /* data 不要落在这颗片的映射上 */
drvSpiFlashRead(f, offset, buf, size);
```

外挂只做文件系统时，可 `drvSpiFlashSetXipEnabled(f, false)`，擦写更快、不走 suspend。

容量：`drvSpiFlashCapacity(f)` 应为 `0x1000000`。对一下 log 里的 mid，应为 `0x1840ef`。

## 6. 规格书里框架没做、一般也不必做的

| 规格书能力 | 现状 | 建议 |
|------------|------|------|
| Quad Page Program `32h` | 只用 `02h` | 不必 |
| Dual/Quad Fast Read 命令 | 控制器 AHB XIP 配，不在 HAL 发 | 保持 |
| Individual Block Lock（WPS=1） | 无 | 保持 WPS=0 |
| 写 SR3（DRV 驱动强度） | 无 | IQ 出厂即可 |
| Chip Erase | 有 API | 应用不要用 |

## 7. 板级与分区（比加表行更容易踩坑）

1. **电压**：2.7–3.6V，不是 1.8V 的 W25QxxJW/LE。
2. **管脚**：IQ 的 QE=1，`/WP`、`/HOLD` 已是 IO2/IO3，不要当 GPIO 拉死。
3. **主片还是外挂**：主片必须 XIP+suspend；外挂可关 XIP。
4. **容量**：当前手表分区是 8MB OpenCPU 表（见 [11_分区说明.md](11_分区说明.md)）。换成 16MB 要改 `CONFIG_FS_SYS_FLASH_*`、下载 JSON、预置资源地址，否则只用到前 8MB 或越界。
5. **软保护**：`block_prohibit[8]` 按 16MB=256 个 64K 块，现有 8 个 uint32 刚好 256 bit，16MB 仍够。
6. **时序**：控制器时钟不要超过手册 133MHz（具体看板级 `spi_config`）。

## 8. 上电核对清单

1. CSV 已加 `W25Q128JV,0x1840ef,...` 并重编 HAL。
2. `halSpiFlashInit` 后 `d->mid==0x1840ef`，`d->capacity==0x1000000`，`d->suspend_en==1`。
3. `StatusCheck` 后 QE=1、WPS=0、非全片误锁（或 Prepare 能解开当前 offset）。
4. 主片：擦一段非代码区时系统仍能进中断（suspend 生效）。
5. `Erase` + `Write` + `ReadCheck` 一页通过。
6. 可选：`4Bh` 读到 8 字节 UID；Security `48h` 读 #1。

---

## 9. 一句话

W25Q128JVSIQ 和已支持的 W25Q64JV 是同一命令集、大一号容量。**驱动/HAL 函数不用新写**，把规格书里的 `9Fh/02h/20h/52h/D8h/75h/7Ah/50h/4Bh/44h/42h/48h` 对到现有 `halSpiFlash*` / `drvSpiFlash*` 即可。落地动作：CSV 精确入表 + 确认 16MB 分区和 WPS=0。
