# 21 页面栈（框架）

`lv_widgets` 里的「页面栈」不是 LVGL 自带的，是 `screen_manager.c` 自己做的一层。  
LVGL 只负责 `lv_scr_load()` 换当前屏；谁在前台、谁还能返回，全由这份链表说了算。

界面总览仍见 [04_UI与屏幕管理.md](04_UI与屏幕管理.md)。本文只讲这层管理器在框架里是什么角色。

---

## 1. 它管什么、不管什么

手表上其实有**两套导航**，不要混成一个栈：

```
┌─ 平面 A：IDLE 页内图层（不进栈）─────────────┐
│  表盘 / 下拉控制中心 / 右拉信息卡 / 上拉消息 / 主菜单  │
│  同一块 lv screen，只改坐标做滑动                     │
└────────────────────────────────────────────────┘
                    │ 点击主菜单等
                    ▼
┌─ 平面 B：screen_manager 页面栈 ──────────────┐
│  通讯录选择 / 通讯录 / 拨号 / 呼叫 / 通话记录 / 闹钟 │
│  每页一块独立 lv screen（parent = NULL）            │
│  用 lv_scr_load 整屏切换                            │
└────────────────────────────────────────────────┘
```

栈只认「全屏业务页」。信息卡、控制中心、主菜单滑进来，都还在 `SCREEN_INDEX_IDLE` 这一页上。

---

## 2. 数据结构

哨兵头 `screen_stack`，后面是双向链表。**尾节点 = 当前前台**。深度上限 `MAX_SCREEN_HISTORY = 10`。

```
screen_stack (哨兵)
    └─ IDLE  ─┬─ SELECT_PB  ─┬─ PB_LIST     ← tail = 当前
              │               └─ (已 pop 掉的不在)
              └─ …
```

每个节点：

| 字段 | 含义 |
|------|------|
| `index` | 页身份（`screen_index_enum`），用来去重、查找 |
| `cb.init / deinit / entry / exit` | 生命周期 |
| `data` | 一般是该页的 `lv_obj_t *` root |

页身份从 `1001` 起编（`SCREEN_INDEX_START = 1000`）。枚举值本身不当数组下标用。

---

## 3. 一页的生命周期

约定：`init` 里 `lv_obj_create(NULL, NULL)` 建独立 screen，挂到 `screen->data`；`entry` 里 `lv_scr_load(data)`。

```
create          分配节点，调用 init        对象树在，还不是 LVGL 当前屏
entry           调用 entry → lv_scr_load   成为前台
exit            暂停（停时钟 task 等）      对象树还在，只是不当前屏
deinit          lv_obj_del + free 节点     彻底拆掉
```

和 Android Activity 接近：`init/deinit` 对创建销毁，`entry/exit` 对前后台。  
中间页 `exit` 之后树不拆，再 `entry` 同一 `index` 是复用，不是重建。

必须在 **GUI 线程**里调这些 API。没有锁。

---

## 4. API 在框架里的语义

业务侧固定写法是 **先 create 再 entry**：

```c
ic_screen_create(SCREEN_PB_LIST, &cb);
ic_screen_entry(SCREEN_PB_LIST);
```

| API | 对栈做什么 | 对当前页做什么 |
|-----|------------|----------------|
| `ic_screen_create(index, cb)` | 同 index 已在则跳过；否则 append + `init` | 先 `exit` 当前 |
| `ic_screen_entry(index)` | 找到该节点，`entry`，并**摘到尾部** | 再 `exit` 当前 |
| `ic_screen_goback()` | 拆尾节点 | `exit`+`deinit` 当前，`entry` 上一页 |
| `ic_screen_close_active()` | 等于 goback | 同上 |
| `ic_screen_goto_idle()` | **整链拆光** | 然后重新 `main_screen_1()` 建 IDLE |

不是教科书栈的两点：

1. **按 index 去重**：同一页不会压两份。再打开通讯录是复用节点，不是再 malloc 一棵树。
2. **entry 可把中间节点挪到尾部**：更像「历史记录 + 调到前台」，不是只能压栈顶。

另外两个硬编码根：

- `entry(IDLE)`：只留链表第一个节点，后面全部 `deinit`。
- `entry(MAINMENU)`：只留前两个节点，后面清掉。  
  但当前工程里**没有** `ic_screen_create(SCREEN_INDEX_MAINMENU)`，这条分支实际走不到；主菜单在 IDLE 的图层上。

`goback` 到 IDLE 就停，IDLE 没有上一页。

## 5. 谁在用栈

```
main_screen_1()
    create+entry IDLE                         栈底，只建一次（除非 goto_idle）

主菜单点击（仍在 IDLE 图层上）
    ic_select_phonebook_or_dial_create()
        create+entry SELECT_PHOBEBOOK_OR_DIAL

    → 通讯录列表 / 拨号 / 通话记录 / 闹钟
        各自 create+entry 对应 index

function/call（模组来电、去电）
    create+entry SCREEN_CALLING / SCREEN_DIAL
    挂断 goback
```

| index | 谁 create | 现状 |
|-------|-----------|------|
| `SCREEN_INDEX_IDLE` | `main_screen_1` | 栈底 |
| `SCREEN_SELECT_PHOBEBOOK_OR_DIAL` | `ic_select_phonebook_or_dial_create` | 用 |
| `SCREEN_PB_LIST` | `ic_entry_pb_list_screen` | 用 |
| `SCREEN_DIAL` / `SCREEN_CALLING` | `function/call/ic_call_phone.c` | 用 |
| `SCREEN_RECENT_CALLOG` / `SCREEN_MISSED_CALLLOG` | calllog | 用 |
| `SCREEN_ALARM_CLOCK` / `_ADD` / `_FRE` | alarm | 用 |
| `SCREEN_INDEX_MAINMENU` / `SCREEN_INDEX_HR` | 无 | 只有枚举和 entry 特判 |

来电可以从任意页 `create+entry CALLING`，等于从业务线程插进一页（仍应切到 GUI 线程再调）。

---

## 6. 和 LVGL、内存的关系

- 栈上每一页都是完整 `lv_obj` 树。`exit` 不释放。
- 路径 `IDLE → 选择 → 通讯录` 会同时活着 **3 棵全屏树**。
- APPIMG 静态 RAM 只有 128KB，深栈比 Flash 更先顶到。
- `goto_idle` 选择「拆光重建」，不要旧 IDLE 节点，时钟 task、抽屉位置一并重来。
- `goback` 回 IDLE 只 `lv_scr_load` 旧 root：主菜单/信息卡上次滑到哪，还在那个坐标，栈不管图层。

---

## 7. 典型路径

```
开机
  main_screen() → main_screen_1()
  栈: [ IDLE ]

表盘右滑信息卡 / 下滑控制中心 / 滑出主菜单
  栈仍是: [ IDLE ]          ← 只动图层

主菜单点击
  栈: [ IDLE, SELECT_PB ]

进通讯录
  栈: [ IDLE, SELECT_PB, PB_LIST ]

goback
  栈: [ IDLE, SELECT_PB ]

再 goback
  栈: [ IDLE ]              ← 回到表盘这棵树，不是「主菜单页」

来电
  栈: [ IDLE, …, CALLING ]

goto_idle
  栈: [] → 再 create IDLE
```

---

## 8. 框架上要注意的点

1. **create + entry 会 exit 两次当前页。** `create` 先 exit，`entry` 再 exit。IDLE 的 `exit` 只是摘掉时钟回调，现在还能扛；以后在 `exit` 里做重事要当心。
2. **create 遇到已有 index 直接 true**，不把节点提到尾部。所以业务必须再 `entry`。
3. **`entry(MAINMENU)` 假定 `head->next` 存在**，当前又没人 create 这一页，调用会踩空。
4. **回调默认当非空用**，`exit`/`deinit`/`entry` 没判空。
5. **满 10 页 create 失败**，只返回 false，没有挤掉最老页。
6. **页身份 = 单例。** 想同时开两个「同类页」做不到，除非新加 enum。
7. 新开一页的固定套路：四个回调 + `lv_obj_create(NULL)` + `create` + `entry`；返回用 `goback`，回桌面用 `goto_idle`。

---

## 9. 一句话

页面栈是 `lv_widgets` 自己的**全屏历史管理器**：用 index 当单例、用四回调管生命周期、用尾节点当前台，最后靠 `lv_scr_load` 交给 LVGL。  
表盘四周的抽屉和主菜单不在这套栈里；从主菜单点进去，才第一次 `create`。
