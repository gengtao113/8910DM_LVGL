# 12 客户开发说明

移远 8910 OpenCPU 上，客户**不编内核**，只编应用镜像（APPIMG）。本手表项目的客户代码都在 `components/ql-application/`，烧进 Flash `0x250000` 起那 2MB。

> 工程根目录：`8910DM_LVGL`  
> 产品：`projects/C56U_HM_SH8`  
> 应用入口：`init/ql_init.c` → `appimg_enter()`  
> 应用产物：`target/C51/app/C51_APP.pac`

分区见 [11_分区说明.md](11_分区说明.md)，怎么编见 [09_编译说明.md](09_编译说明.md)，包怎么认见 [10_编译产物说明.md](10_编译产物说明.md)。OpenCPU 模型本身见 [14_OpenCPU开发说明.md](14_OpenCPU开发说明.md)。

---

## 1. 客户和模组厂各编什么

```
底包（移远 / 方案）                    客户应用（APPIMG）
BOOT + APP + modem + FS + 分区表       ql-application
8915DM_cat1_open.img                   C51_APP.img
预编译 ql-kernel/libs/*.a              调 ql_lcd_* / ql_gpio_* / ql_voice_call_* …
```

| 谁 | 改什么 | 产物 |
|----|--------|------|
| 模组 / 方案 | `kernel`、`hal`、`driver`、modem、NV、`partinfo` | `8915DM_cat1_open_C51.pac` |
| 客户 | `ql-application/`、`projects/<产品>/` | `app/C51_APP.pac` |
| 整机交货 | 上面两份合成 | `8915DM_cat1_open_C51_merge.pac` |

日常改 UI / 通话 / 触控，只盯 APPIMG。换屏驱芯片、换 Flash 容量、改分区、改 VoLTE，回到底包。

---

## 2. 应用怎么被拉起来

`target.config` 里 `CONFIG_APPIMG_LOAD_FLASH=y`。内核从 APPIMG 区加载镜像后调用：

```c
int appimg_enter(void *param)
{
    ql_rtos_task_create(..., "ql_init", ql_init_demo_thread, ...);
}
```

本项目 `ql_init_demo_thread()` 里真正打开的是：

```c
ql_lvgl_app_init();   // GUI 线程、LVGL、屏 / 键 / 触摸
ic_main_entry();      // 通话回调、通话记录
```

官方自带的 HTTP/MQTT/LCD 等 `*_demo` 大多注释掉或关 feature。开关在 `ql_app_feature_config.h.in` / `ql_target.cmake`（由 `projects/C56U_HM_SH8/` 覆盖）。

硬件不直接碰寄存器，走 `components/ql-kernel/inc/` 的 **ql_api**。

## 4. 一天怎么开发

1. 改 `ql-application/`（或先改 `projects/C56U_HM_SH8/` 再整编一次把配置拷进去）。  
2. 编译（Linux 只留 `build_all.sh`）：

```bash
./build_all.sh                    # 套 C56U_HM_SH8，增量 release
./build_all.sh new C56U_HM_SH8    # 清 out 或配置大改
```

3. 下载：

| 情况 | 烧哪个 |
|------|--------|
| 底包已在机器上，只改了应用 | `target/C51/app/C51_APP.pac` |
| 新板、清过片、改过分区 / 底包 | `target/C51/8915DM_cat1_open_C51_merge.pac` |

4. 调试应用：`app/C51_APP.elf` + `.map`。内核崩溃才看顶层 `8915DM_cat1_open.elf`。

改了 `lv_widgets/assets/images/` 或 `image_res.csv` 才需要 `./build_all.sh resgen`（要系统 `php`）。新生成的 `IMG_*.c` 还要写进 `lv_widgets/CMakeLists.txt`。

Windows 对应：`new_prj.bat C56U_HM_SH8` + QFlash。PC 模拟器在 `simulator/lvgl/`（VS 工程），只辅助排布局，**不能代替板上 APPIMG**。

---

## 5. 客户通常不改什么

- `components/kernel`、`hal`、`driver`（含 LCD 控制器底层、SPI NOR）  
- `components/ql-kernel/libs/*.a`  
- modem 镜像、`nvitem`、`partinfo_8910_8m_opencpu.json`

这些变了必须重出底包，不能只交 `C51_APP.pac`。

`ql_target.cmake` 有的开关两边 CMake 都会读，不要当成“只影响 APP”。

---

## 6. 体积和分区约束

APPIMG 固定 **2MB**（`CONFIG_APPIMG_FLASH_SIZE=0x200000`）。本机一次 release 的 `C51_APP.img` 大约 1.6MB。运行时静态 RAM 只有 **128KB**（`0x80FA0000`），`malloc` 走内核堆。详见 [13_内存划分说明.md](13_内存划分说明.md)。

图、字库、TTS 再涨先看 `target/C51/app/C51_APP.img`。满了：裁资源，或改分区（改分区 = 底包 + 整包重下）。

根文件系统 `/` 只有 320KB，不要往 `/` 丢大文件。

---

## 7. 和 APPIMG 的关系（再收一句）

- **写功能、改界面、调通话/触控**：在 `ql-application`，产物就是 APPIMG。  
- **换屏、换 Flash、改 8MB 表、改 VoLTE**：底包，和模组方案一起改。  
- 量产 / 全量升级用 **merge.pac**，避免底包和 APP 对不齐。

./build_all.sh

# 新机：target/C51/8915DM_cat1_open_C51_merge.pac
