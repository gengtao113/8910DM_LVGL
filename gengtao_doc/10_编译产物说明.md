# 10 编译产物说明

`./build_all.sh` 成功后，中间文件在 `out/`，交货目录在 `target/<版本号>/`。

> 工程根目录：`8910DM_LVGL`  
> 芯片 target：`8915DM_cat1_open`  
> 本项目 release 版本号：`C51` → `target/C51/`  
> 本项目 debug 版本号：`C51V` → `target/C51V/`  
> `C51` / `C51V` 只是标签，不是芯片型号。

编译怎么跑见 [09_编译说明.md](09_编译说明.md)。本文只讲编出来的东西怎么认、怎么用。

---

## 1. 目录关系

```
out/8915DM_cat1_open_release/     cmake / ninja 中间目录（debug 则是 _debug）
        hex/                      各镜像、pac 的原始产出
        ↓  build_all.sh 收包
target/C51/
        8915DM_cat1_open_C51_merge.pac   ← 整机下载用这个
        8915DM_cat1_open_C51.pac         ← 底包（无本次 APP）
        8915DM_cat1_open.elf / .map      ← AP 调试
        app/                             ← OpenCPU 应用分区
        prepack/                         ← hex 拆件 + codesize
```

`out/` 可删，下次 `new` 会重建。`target/` 是给人拷走、给 QFlash 用的。

## 2. 顶层文件（`target/C51/`）

以本机一次 release 为例（大小会随代码变）：

| 文件 | 约大小 | 作用 |
|------|--------|------|
| **`8915DM_cat1_open_C51_merge.pac`** | 7.2M | **整机烧录。** 底包 + 本次 APP 合成 |
| **`8915DM_cat1_open_C51.pac`** | 5.7M | 内核 / modem / boot / 分区，**不含**这次编的 LVGL 应用 |
| **`8915DM_cat1_open.elf`** | 17M | AP 带符号，Trace32 / gdb / addr2line |
| **`8915DM_cat1_open.map`** | 4.0M | 链接图：函数地址、段大小 |

`.elf` / `.map` **不能直接烧**。烧的是 `.pac`（或拆开的 `.img`）。

### 2.1 两个 pac 差在哪

OpenCPU 把 **AP 内核** 和 **应用镜像（APPIMG）** 分开：

```
C51.pac          = boot + fdl + AP 内核 + modem + NV + 分区
                   里面的 APP 槽是占位或旧图

C51_APP.pac      = 这次编的 UI（lv_widgets / 通话 / 通讯录）

C51_merge.pac    = dtools pacmerge，用 C51_APP 替换底包里的 APPIMG
```

脚本对应关系：

```text
dtools pacmerge --id APPIMG,PS  \
    8915DM_cat1_open_C51.pac    \
    app/C51_APP.pac             \
    8915DM_cat1_open_C51_merge.pac
```

有 `ql_prepack.opt` 时还会多合 PREPACK/NV。

### 2.2 怎么选

| 场景 | 用哪个 |
|------|--------|
| 产线 / 刷整机 / 第一次上机 | **`*_merge.pac`** |
| 底包不变，只换 UI | `app/C51_APP.pac` |
| 只要协议栈/内核、不要这次 UI | `*_C51.pac`（少见） |
| 看崩溃 PC | `.elf` + `.map` |

## 3. `app/`：应用分区

| 文件 | 作用 |
|------|------|
| `C51_APP.pac` | 只更新应用分区（单独下载 / FOTA） |
| `C51_APP.img` | 未签名应用镜像 |
| `C51_APP.sign.img` | 签名后，打进 pac 的那份 |
| `C51_APP.elf` / `.map` | 应用侧调试（符号比 AP 内核 elf 小一圈） |

手表 UI 走这条：`ql-application` → APPIMG，不是全部链进 `8915DM_cat1_open.elf` 的同一条“应用段”交货。内核 elf 里仍有大量系统代码；界面/业务以 APP 镜像为准去烧。客户日常怎么改、什么时候只下这个包见 [12_客户开发说明.md](12_客户开发说明.md)。

debug 时文件名是 `C51V_APP.*`，角色相同。

## 4. `prepack/`：拆开的中间件

`hex/` 先整份拷到这里，再把主 elf/map/pac 挪到 `target/C51/` 根上。一般 **不用手拿这里的文件去烧**，它们已经打进上面的 pac。

### 4.1 下载与启动

| 文件 | 作用 |
|------|------|
| `fdl1.img` / `fdl1.elf` | 一级下载器。QFlash 先下 FDL，再写 Flash |
| `fdl2.img` / `fdl2.elf` | 二级下载器 |
| `flash_test_fdl.*` | Flash 测试用 FDL，产线/研发工具，不是量产包必烧项 |
| `boot.img` / `boot2.img` | 一级 / 二级 boot |
| `*.sign.img` | 对应镜像的签名版（安全启动打开时用） |

### 4.2 固件与协议栈

| 文件 | 作用 |
|------|------|
| `8915DM_cat1_open.img` | AP 主程序去掉调试段后的镜像（已进底包 pac） |
| `cat1_UIS8915DM_BB_RF_SS_cus.img` | modem。本项目 VoLTE + 单卡用 `SS_cus`；双卡是 `DS`，关 VoLTE 带 `NoVolte` |
| `cat1_UIS8915DM_BB_RF_SS_cus_nvitem.bin` | NV：射频/校准/配置 |
| `partinfo.bin` | 从 `partinfo_8910_8m_opencpu.json` 生成的分区表，布局见 [11_分区说明.md](11_分区说明.md) |
| `target.cmake` | 这次 CMake 展开的开关快照 |

### 4.3 体积统计

`codesize.py` 读 `.map` 生成：

| 文件 | 内容 |
|------|------|
| `outlib.csv` | 按静态库 |
| `outobj.csv` | 按 `.o` |
| `outsect.csv` | 按段（text/rodata/bss…） |

编完日志里那行 `total: text,rodata,data,bss,...` 同源。

### 4.4 其它

| 文件 | 作用 |
|------|------|
| `appimg_flash_delete.pac` | 擦应用区的小包，一般不用 |
| `*_prepack.cpio` | prepack 文件系统镜像（本项目常为空或很小） |
| `examples/` | 若有，脚本会再拷一份到 `app/` |

## 5. 和烧录的对应关系

QFlash 一类工具打开的是 **pac**。pac 里面按 id 装着多份 img：

```
FDL1 / FDL2     下载器
BOOT / BOOT2    启动
AP              8915DM_cat1_open.img
PS / modem      cat1_UIS8915DM_BB_RF_*.img
NV              nvitem.bin
APPIMG          C51_APP.img（merge 之后才是本次 UI）
分区表          partinfo
```

`pacmerge --id APPIMG,PS` 的意思：用第二个 pac 里的 APPIMG（以及 PS 相关项）覆盖第一个 pac 的同名槽。

## 6. release 和 debug 两套产物

| | release | debug |
|--|---------|-------|
| 命令 | `./build_all.sh` 或 `new C56U_HM_SH8` | `./build_all.sh debug C56U_HM_SH8` |
| 目录 | `target/C51/` | `target/C51V/` |
| 中间目录 | `out/8915DM_cat1_open_release/` | `out/..._debug/` |
| 看门狗 `CONFIG_WDT_ENABLE` | 开 | 关（`gBsWatchdogReset` 仍保留符号，便于链预编译库） |
| 文件角色 | 相同 | 相同，pac 文件名带 `C51V` |

两套不要混着烧：debug 便于断点，release 才是量产看门狗行为。

## 7. 名字怎么读

以 `8915DM_cat1_open_C51_merge.pac` 为例：

```
8915DM_cat1_open   BUILD_TARGET（脚本写死）
C51                版本标签（build_all 第三个参数 / 产品入口默认）
merge              已合入 APP
pac                移远下载包
```

`EC600UCN_LB` 不会出现在文件名里，它只决定读哪份 `ql-config` 和 NV。

---

## 8. 最短结论

- 给人、给工厂：**`target/C51/8915DM_cat1_open_C51_merge.pac`**
- 只改了 C / UI：增量编完仍交这个 merge 包，或只下 `app/C51_APP.pac`
- 对地址：同目录 `.elf` + `.map`
- `prepack/` 是拆件仓库，不是第二套交货包
