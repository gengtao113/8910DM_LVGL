# 09 编译说明

8910 OpenCPU 用 **CMake + Ninja + arm-none-eabi-gcc**。Windows 用自带 bat；Linux 用同目录下的 `.sh`（参数与 bat 对齐）。

> 工程根目录：`8910DM_LVGL`  
> 当前手表项目：`projects/C56U_HM_SH8`  
> 模组配置：`EC600UCN_LB`  
> 芯片 target：`8915DM_cat1_open`

---

## 1. 能不能在 Linux 编

**可以编固件。** 仓库已带 Linux 工具链：

| 路径 | 用途 |
|------|------|
| `prebuilts/linux/gcc-arm-none-eabi/` | `arm-none-eabi-gcc` |
| `prebuilts/linux/cmake/`、`prebuilts/linux/bin/ninja` | 生成 / 构建 |
| `tools/linux/dtools` | 打包、pacmerge |
| `tools/launch.sh` | 把上述路径加入 `PATH` |

注意：

- 官方日常入口是 `.bat`；Linux **只留** `build_all.sh`（`new_prj.sh` / `debug_prj.sh` / `resgen.sh` 已并进去）。
- LVGL **PC 模拟器**：Windows 仍用 VS 工程；Ubuntu 用 SDL2，`./build_lvgl_sim.sh run`（见 `simulator/lvgl/LinuxSDL2/`，对照 X-TRACK LinuxSDL2）。只辅助排布局，不能代替板上 APPIMG。
- `resgen` 依赖 PHP。Windows 用 `tools/php/php.exe`；Linux 需系统 `php`。不改图可以不跑。

## 2. 编译在干什么

```
projects/<项目>/          拷到 ql-application（feature / 表盘）
        ↓
components/ql-config/build/<模组>/8915DM_cat1_open/
        ↓  环境变量 + NV 拷到 prebuilts/modem
cmake -G Ninja  →  out/8915DM_cat1_open_<debug|release>/
        ↓
ninja                     出 hex / elf / pac
        ↓
整理到 target/<版本号>/   再 dtools pacmerge
```

CMake 必读环境变量：

| 变量 | 含义 | 本项目常用值 |
|------|------|----------------|
| `ql_buildproj` | 模组目录名 | `EC600UCN_LB` |
| `BUILD_TARGET` | 内核 target | `8915DM_cat1_open`（脚本写死） |
| `BUILD_RELEASE_TYPE` | debug / release | release 默认 |
| `ql_app_ver` | 应用包版本 | `<版本号>_APP`，如 `C51_APP` |
| `quec_ims_feature` | VoLTE | `y` / `n` |
| `ql_dsim_cfg` | 双卡 | `y` / `n` |
| `ap_ram_offset` / `ap_ram_size` | AP 内存 | VoLTE 开/关两套 |
| `partitionfile` | 分区 JSON | 8M opencpu ± novolte ± ds ± extflash |

`CMakeLists.txt` 用  
`components/ql-config/build/${ql_buildproj}/${BUILD_TARGET}/target.config`。  
这个目录不存在会直接失败。

`target/C51/` 是**已编过的产物目录**，不是 CMake 的 `BUILD_TARGET`。`new_prj` 里的 `C51` 是版本标签。

## 3. 脚本对照

| Windows（官方 bat，保留） | Linux（只留 `build_all.sh`） |
|---------------------------|------------------------------|
| `new_prj.bat <项目>` | `./build_all.sh new C56U_HM_SH8` |
| `debug_prj.bat <项目>` | `./build_all.sh debug C56U_HM_SH8` |
| `build_all.bat ...` | `./build_all.sh r\|new <模组> <版本> ...` |
| `r.bat` | `./build_all.sh` 或 `./build_all.sh C56U_HM_SH8` |
| `clean.bat` | `./build_all.sh clean` |
| `resgen.bat` | `./build_all.sh resgen` |
| `help.bat` | `./build_all.sh -h` |

`new_prj` 会拷（有才拷）：

- `projects/<项目>/ql_target.cmake`
- `projects/<项目>/ql_app_feature_config.h.in`
- 可选表盘：`clockface_table.c`、`digital1/2/3`  
  当前 `C56U_HM_SH8` 只有前两个 cmake 文件。

## 4. 命令怎么写

### 4.1 本项目一键（推荐）

Linux 可以直接写产品名（`projects/` 下目录）：

```bash
cd /path/to/8910DM_LVGL
./build_all.sh                    # 默认 C56U_HM_SH8，增量 release
./build_all.sh C56U_HM_SH8        # 同上
./build_all.sh new C56U_HM_SH8    # 清 out 后整编
./build_all.sh debug C56U_HM_SH8  # 清 out + debug（C51V）
./build_all.sh resgen             # 只转图，需 php
```

Windows：

```bat
new_prj.bat C56U_HM_SH8
debug_prj.bat C56U_HM_SH8
```

等价于：

```text
build_all new EC600UCN_LB C51  VOLTE SINGLESIM     → release
build_all new EC600UCN_LB C51V VOLTE SINGLESIM     → debug（Linux 用环境变量）
```

### 4.2 build_all 参数

```text
./build_all.sh <动作> <模组> <版本号> [VOLTE] [DSIM] [EXTFLASH]
```

| 位置 | 取值 | 说明 |
|------|------|------|
| 动作 | `new` / `n` | 先删 `out/` 再编 |
| | `r` | 增量 |
| | `debug` | 清 out + debug（产品名入口） |
| | `resgen` | 只转图 |
| | `clean` / `c` | 只删 `out/` |
| 模组 | `EC600UCN_LB` 等 | `components/ql-config/build/` 下目录 |
| 版本号 | 如 `C51` | 产物目录 `target/C51/` |
| VOLTE | `VOLTE` / `NOVOLTE` | 默认 NOVOLTE；本项目用 VOLTE |
| DSIM | `SINGLESIM` / `DOUBLESIM` | 默认单卡；`SSIM` 也当单卡 |
| EXTFLASH | `EXTFLASH` / 其它 | 有外挂 Flash 才写 EXTFLASH |

Linux 发布类型用环境变量（bat 靠调用方设 `outputtype`）：

```bash
BUILD_RELEASE_TYPE=debug ./build_all.sh new EC600UCN_LB C51V VOLTE SINGLESIM
```

增量：

```bash
./build_all.sh r EC600UCN_LB C51 VOLTE SINGLESIM
```

### 4.3 不用封装、手搓（Linux）

```bash
cp projects/C56U_HM_SH8/ql_target.cmake components/ql-application/
cp projects/C56U_HM_SH8/ql_app_feature_config.h.in components/ql-application/

export ql_buildproj=EC600UCN_LB
export BUILD_TARGET=8915DM_cat1_open
export BUILD_RELEASE_TYPE=release
export quec_ims_feature=y
# 以及 bat 里那套 ap_ram / partition / modemdir …

# 不要用 launch.sh 选 target/C51，会和 8915DM_cat1_open 打架
export PATH="$PWD/prebuilts/linux/bin:$PWD/prebuilts/linux/cmake/bin:$PWD/prebuilts/linux/gcc-arm-none-eabi/bin:$PWD/tools/linux:$PATH"

mkdir -p out/8915DM_cat1_open_release && cd out/8915DM_cat1_open_release
cmake ../.. -G Ninja
ninja
```

日常用 `./build_all.sh` 即可，它会设 PATH、拷 NV、收包。

## 5. VoLTE / 双卡 / 外挂 会改什么

| 组合 | modem 目录 | 分区 JSON | AP RAM |
|------|------------|-----------|--------|
| VOLTE + 单卡（本项目） | `..._SS_cus` | `partinfo_8910_8m_opencpu.json` | offset `0xC00000` size `0x400000` |
| VOLTE + 双卡 | `..._DS_cus` | `..._opencpu_ds.json` | 同上 |
| NOVOLTE + 单卡 | `..._SS_NoVolte_cus` | `..._opencpu_novolte.json` | offset `0x980000` size `0x680000` |
| NOVOLTE + 双卡 | `..._DS_NoVolte_cus` | 同上（脚本未换 novolte_ds 文件名） | 同上 |
| 再加 EXTFLASH | 同上 | 文件名加 `_extflash` | 不变 |

NV 从 `ql-config/build/<模组>/nvitem/` 拷到 `prebuilts/modem/8910/<modemdir>/nvitem/`，并按 VoLTE/双卡选 `.prj`。

## 8. 工具链与环境

Linux 脚本会把这些**插到 PATH 最前**，避免用到系统/buildroot 的 ninja：

```
prebuilts/linux/bin
prebuilts/linux/cmake/bin
prebuilts/linux/gcc-arm-none-eabi/bin
prebuilts/linux/nanopb
tools
tools/linux
```

`build_all.sh` 启动时还会：

- 给上述 ELF 补 **执行位**（仓库 / zip / 从 Windows 拷过来时常是 `644`）。git 可能看到一堆权限变化，**不要把 prebuilts 的 mode 改动提交上去**。
- 去掉 `prebuilts/linux/nanopb/protoc` 的 CRLF。这个包装脚本负责给 32 位 `protoc.bin` / `protoc-gen-nanopb` 设 `LD_LIBRARY_PATH`；带 `\r` 时找不到同目录的 `libz.so.1`。
- 若 `tools/linux/lib/` 没有 ICU 55，从 Ubuntu xenial 拉 `libicu55`（`dtools` 的 Qt5 依赖）。这几份 `.so` 不要提交。

**不要**把 `prebuilts/linux/nanopb` 加进全局 `LD_LIBRARY_PATH`：里面的 `libz.so.1` 是 i386，会搅乱 64 位 cmake/dtools。

还需要系统 **python3**（生成 nor 属性表、codesize），以及能跑 i386 的 `libc6-i386`（nanopb 是 32 位）。`dtools` / cmake / gcc 是较老的 x86-64 glibc 二进制。

Windows 对应 `prebuilts/win32/` + `tools/win32/`，由 bat 加 PATH。

## 9. 常见失败

| 现象 | 原因 |
|------|------|
| `ninja --version` **Permission denied**；CMake 报 *readable but not executable* | `prebuilts/linux` 下 ELF 没有 `+x`（Windows/zip 常见）。`build_all.sh` 会自动补 |
| `as: 未识别的选项 "-meabi=5"` | gcc 找到的是系统 `as`，不是 `prebuilts/.../arm-none-eabi/bin/as`（同样缺 `+x`）。脚本会一并补 |
| `which cmake=/usr/bin/cmake`，`which ninja` 指向 100ask / buildroot | 同上：SDK 工具没有执行位，`command -v` 跳过它们。补 `+x` 后应指向本仓库 `prebuilts/linux/...` |
| `target.config is not exist` | `ql_buildproj` 或 `BUILD_TARGET` 不对；应用 `EC600UCN_LB` + `8915DM_cat1_open` |
| `BUILD_TARGET is empty` | 没走脚本、没 export |
| cmake/ninja 不是 SDK 的 | PATH 里先有别的 ninja；看脚本打印的 `which cmake/ninja/gcc` |
| VOLTE 与 CCSDK 冲突 | `ql_target.cmake` 关了 VOLTE 却传 `VOLTE` |
| 只编了前半、没有 pac | ninja 中途失败；看 `out/...` 日志 |
| `php not found, skip image gen` | 没装 `php-cli`；**不改图可以忽略**，已有 `IMG_*.c` 照常编 |
| `dtools: libicui18n.so.55: cannot open shared object file` | `dtools expgen` 在 **ninja 阶段**就要（不是只在最后 pacmerge）。脚本会把 xenial 的 ICU 55 放到 `tools/linux/lib/`（dtools 的 RPATH 是 `$ORIGIN/lib`） |
| `protoc-gen-nanopb: libz.so.1: cannot open shared object file` | nanopb 是 **i386**，库在 `prebuilts/linux/nanopb/libz.so.1`。常见原因是 `protoc` 包装脚本带 CRLF。脚本会转成 LF。本机还需 `libc6-i386` |
| `liblto_plugin.so: 文件过短` | Windows/git 把 `.so` 符号链接存成 22 字节文本（内容是 `liblto_plugin.so.0.0.0`）。脚本会改回真正的 symlink |
| `queue.c: unknown type name 'osiThread_t'` | `osiEventSpaceCount` 实现只应在 `osi_freertos.c`；`queue.c` 里那份是重复粘贴，已删 |
| `undefined reference to gBsWatchdogReset`（debug 链接） | `CONFIG_WDT_ENABLE` 只在 release 打开，debug 原先不编这个变量；`libql_api_dev.a` / `libql_at.a` 却无条件引用。已在 `osi_blue_screen.c` 始终提供该符号 |
| `launch.sh` 选了 `C51` | `C51` 是产物文件夹，不是 BUILD_TARGET |
